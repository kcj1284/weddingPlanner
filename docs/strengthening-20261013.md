# Prototype·GrillMe 보강 기록

## 적용 범위

최근 초대·게스트 참여와 장소 검색의 기존 규칙을 기준으로 보강했다. UI 전면 개편·새 참여 정책·외부 배포는 추가하지 않았다. 우선순위 질문은 별도로 제시했으며 응답 전에는 기존 규칙과 충돌하는 코드 오류만 처리했다.

GrillMe의 grilling/domain-modeling 절차로 저장소 사실을 점검하고 용어를 CONTEXT.md에 정리했다. 코드 검토는 별도 읽기 전용 에이전트가 수행했다. 개인 초대, 단체 초대, 만료, 취소, 재발급을 구분한다. 개인 취소는 참여와 투표를 제거하고, 만료·단체 닫기는 기존 참여를 유지하는 현재 정책을 바꾸지 않았다.

## 확인한 문제와 수정

1. 단체 링크 재참여 시 빈 개인 토큰을 반환해 주소에서 재접속 링크가 사라졌다. 같은 게스트의 유효한 암호화 개인 코드를 반환하도록 수정했다. 해시 전용 이전 개인 링크만 있으면 유효한 단체 초대와 현재 게스트 세션을 근거로 같은 신원의 복구 링크를 발급한다. 새로운 참여자로 만들지 않는다.
2. 만료 장소 목록은 뒤에서 갱신했지만 후기 캐시가 유효하면 pending=false여서 화면이 갱신 결과를 받지 못했다. 장소 목록 갱신 상태를 별도로 반환하고 상태 조회를 유지하며, 화면에도 최신 목록 확인 중이라고 안내한다.
3. 같은 식당 이름과 같은 시·구를 가진 지점이 후기 캐시 키를 공유할 수 있었다. 전체 주소를 캐시 신원에 포함했다. 검색 질의는 상호명과 시·구 정보로 유지하며 검색된 글이 특정 지점의 실제 방문 후기라고 단정하지 않는다.
4. 만료된 초대가 목록에서 초대 가능 또는 참여 중으로만 표시됐다. 서버가 현재 시간 기준 만료 상태를 반환하고 개인·단체 초대 모두 초대 만료로 표시한다.

## Prototype

질문: 같은 게스트가 단체 링크를 다시 누른 뒤 세션이 끝나도 자기 이름과 투표로 재접속할 수 있는가?

단일 HTML 실험 화면은 현재 동작과 개인 링크 유지안을 비교한다. 자유 조작과 네 시나리오(단체 재참여, 코드 재발급, 단체 닫기, 만료와 취소), 전체 관련 상태 표시를 제공한다. 실제 DB나 계정에 연결하지 않는다. artifacts/prototypes/invite-lifecycle.prototype.html을 파일로 직접 열어 사용할 수 있다.

원본 실험은 로컬 브랜치 **codex/prototype-invite-lifecycle-20261013**, 커밋 **40d2280066d3401da68c970bc191d58f19d83ee7**에 보관했다. 실제 서비스 소스에는 실험 HTML을 남기지 않았다. 브랜치에는 이전 HEAD 위에 실험 파일만 추가했으며 이번 작업의 다른 미커밋 변경은 기존 체크아웃과 인덱스에 그대로 있다. 원격 저장소로 올리지 않았다.

결론: 재참여는 같은 신원뿐 아니라 사용 가능한 개인 재접속 링크도 유지해야 한다. 이 조건과 기존 정책은 실제 구현 테스트로 검증했다. 내장 브라우저는 file URL을 허용하지 않으므로 실험 HTML의 자동 브라우저 미리보기는 수행하지 않았다. 파일 자체는 더블클릭으로 사용할 수 있다.

## 검증과 남은 결정

전체 자동 테스트 47개 통과. 동일 세션 재참여의 개인 코드 유지, 이전 링크 신원 복구, 만료 표시, 장소 목록 갱신 상태 및 지점별 캐시 신원을 추가 확인했다. Prototype 자체에는 별도 테스트를 작성하지 않았다.

추후 정책 결정: 세션과 개인 링크를 모두 잃은 게스트의 본인 확인 방식, 개인 취소 시 투표 기록 보존 여부, 실제 네이버 키 연결 후 검색 품질·한도 확인, 카카오톡 모바일 최종 전송 확인. 이름만으로 다른 사람의 신원을 복구하는 정책은 도입하지 않았다.
브라우저 추가 검증: 합성 게스트 보강 검증이 공통 링크로 참여한 뒤 동일 링크를 다시 열어도 개인 재접속 URL이 동일하게 유지됨 확인. 호스트 화면으로 복원했고 로컬 최종 빌드 HTTP 200을 확인했다.
