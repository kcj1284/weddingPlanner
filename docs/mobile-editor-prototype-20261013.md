# 모바일 청첩장 편집 UX 비교

사용자가 보강 우선순위를 모바일 화면과 청첩장 편집 UX로 선택했다. Prototype UI 워크플로에 따라 기존 invitation.html에서 variant=A/B/C로 화면 구조를 비교한다. 로컬 프로필에서만 비교 모드를 활성화하며 로그인·기존 데이터 조회는 유지한다. 실험 중 입력은 별도 메모리에만 저장하고 실제 저장·발행 API를 호출하지 않는다.

- A — 단계별 안내: 하나의 작업에 집중하고 이전·다음과 접힌 미리보기를 제공한다. 처음 만드는 사람에게 권장한다.
- B — 미리보기 중심: 초대장을 보면서 이름·문구·사진 설정을 하단 편집 패널로 연다.
- C — 전체 항목 목록: 모든 제작 항목을 접히는 목록에 두고 원하는 항목부터 편집한다.

하단 화살표와 좌우 키로 전환하며 variant 값이 URL에 반영된다. 입력 중 좌우 키는 전환에 사용하지 않는다. 모바일 390px에서 세 대안과 편집 패널·전환을 확인했으며 브라우저 오류 로그는 없었다. 화면은 artifacts/editor-prototype-A.png부터 C.png에 기록했다. 프로토타입에는 별도 테스트를 작성하지 않았다.

사용자가 A ‘한 단계씩 안내’를 선택하여 실제 편집기에 적용했다. 디자인 → 예식 정보 → 사진 → 문구 편집 → 축의금 → 확인·공유의 여섯 단계를 이전·다음으로 진행한다. 현재 단계, 진행률, 단계별 설명과 바로가기 선택을 제공한다. 현재 단계의 필수 입력이 누락되면 다음 진행을 막고 해당 입력으로 이동한다. 미리보기에서 돌아올 때 같은 단계와 모바일 스크롤 위치를 유지한다. 마지막 단계에는 필수 정보 6개, 계좌 공개 여부와 저장·발행 상태를 요약한다. 웨딩 타임즈의 신문 문구 설정도 문구 편집 단계에서 제공한다.

비교 실험 전체는 로컬 브랜치 `codex/prototype-mobile-editor-20261013`, 커밋 `e457371ac32619830c9f4e7bef1aca63c7897068`에 보관했다. 실제 서비스에서는 variant 전환 훅과 실험용 JS/CSS를 제거했다. 이 브랜치는 로컬 보관이며 GitHub에 푸시하지 않았다.

검증: 로컬 패키지 빌드와 JS 구문 검사 통과. 모바일에서 필수 입력 누락 시 같은 단계 유지·입력 포커스, 단계 이동, 미리보기 후 단계 복귀, 최종 요약, 비공개 저장과 재접속 후 입력 복원을 확인했다. 신문형 문구 설정의 단계 이동도 확인했다. 가로 넘침과 브라우저 오류가 없었다. 화면 기록은 `artifacts/guided-editor-review-mobile.png`이다. 합성 이름 ‘UX검증신랑 / UX검증신부’의 비공개 검증용 청첩장 1개를 저장했고 발행하지 않았다. 이전 보강의 자동 테스트 47개는 통과했으며 이번 프런트엔드 변경은 브라우저로 검증했다.

GrillMe 검토 기준: 모바일에서 현재 단계와 남은 작업을 알 수 있는가, 미리보기 후 같은 편집 위치로 돌아오는가, 저장과 공개 반영의 차이를 이해할 수 있는가, 자유 편집과 신문형 문구 편집의 차이를 찾을 수 있는가. 공개 정책이나 기존 청첩장 데이터를 변경하지 않는다.
