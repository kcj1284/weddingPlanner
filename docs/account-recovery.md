# 이메일 인증과 계정 복구

## 이용 방법

일반 호스트 회원가입에서 복구 이메일을 입력한다. 가입·로그인 후 인증 메일을 요청하고 설정 화면으로 이동한다. 메일 링크의 **이메일 인증 완료**를 눌러야 복구 연락처로 등록된다. 발송 실패 시 계정은 이미 만들어졌으므로 설정 화면에서 다시 요청한다.

기존 회원은 로그인 후 상단 **복구 이메일**에서 주소와 현재 비밀번호를 입력한다. 이메일 변경도 현재 비밀번호가 필요하며 새 주소 인증 전까지 기존 주소를 유지한다. 인증된 이메일은 일반 계정 한 개에 연결된다. 이메일 없는 이전 계정·API 등록은 호환되며 복구를 쓰려면 별도로 인증한다.

로그인 화면의 **아이디 찾기**는 인증된 복구 이메일이 일치하면 마스킹된 아이디를 화면에 즉시 표시한다. 끝 4자리를 `*`로 표시하고 4자 이하인 아이디는 전체를 가린다. 예: `wedding_host` → `wedding_****`, `host` → `****`, `abc` → `***`. 서버가 마스킹하여 반환하며 원문 아이디나 안내 메일을 보내지 않는다. 미일치·미인증 이메일은 찾지 못했다는 안내를 표시한다. 이메일 앞뒤 공백과 대소문자는 정규화한다.

**비밀번호 재설정**은 계속 이메일의 일회성 링크에서 새 비밀번호와 확인을 입력한다. 최소 8자·최대 64자이며 한글·공백·이모지도 허용한다. 연속·반복 금지 규칙과 문자 종류 조합 강제는 없다. [생성 정책](credential-policy.md). 변경 후 기존 세션은 다음 API 요청에서 차단된다. 소셜 계정은 해당 제공자에서 복구하고 게스트는 초대 재전송을 이용한다.

## 구현

- Flyway V6: 인증 연락처·인증/재설정 토큰·요청 제한 테이블, 세션 버전 필드. 기존 모임·투표·청첩장 유지.
- 인증 30분, 재설정 15분. 임의 256비트 토큰의 해시만 저장. URL fragment에서 토큰을 읽고 주소에서 제거. 확인은 명시적 제출이며 CSRF 검사.
- 새 요청은 이전 동일 목적 링크 무효화. 연락처 인증·비밀번호 변경은 모든 미사용 링크 무효화. 새 비밀번호 설정 시 현재 인증 연락처 재확인.
- 요청 제한: IP당 15분에 20회, 이메일당 5회. 아이디 확인에도 적용한다. 실제 SMTP의 공개 비밀번호 재설정 요청은 제한된 큐에서 처리하고 실패 로그에 계정·토큰을 남기지 않는다.
- SMTP 미설정 시 local/test에서만 메일 파일로 대체. 운영에서는 요청 거절. local 메일함은 `artifacts/mailbox`, 테스트는 `artifacts/test-mailbox`이며 HTTP로 공개하지 않는다.

## SMTP 설정

환경변수: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `MAIL_FROM`, `PUBLIC_BASE_URL`. 기본 587 + STARTTLS 필수, 인증서 호스트명 검증. 465는 `SMTP_SSL=true`, `SMTP_STARTTLS=false`로 설정한다.

```powershell
./scripts/set-smtp.ps1 -SmtpUsername '콘솔의 SMTP Login' -FromEmail '인증한 발신 이메일'
```

숨겨진 프롬프트에서 SMTP 키를 입력한다(API 키가 아니다). `data/smtp-password.dpapi`는 현재 Windows 사용자에 묶인 암호화 파일, `data/smtp-settings.json`은 비밀값 없는 설정이다. 실행 스크립트가 읽으며 환경변수가 우선한다. data/artifacts는 Git 제외. 배포 서버에서는 비밀값 관리 기능으로 전달하고 `PUBLIC_BASE_URL`을 실제 HTTPS 주소로 변경한다. localhost 링크는 다른 기기에서 사용할 수 없다.

## Brevo 연결 결과 (2026-10-13)

사용자가 가입·본인 확인을 완료했다. 서버 `smtp-relay.brevo.com`, 포트 587, 콘솔 SMTP Login, 발신 주소 `chungmo7942@gmail.com` 연결. 발신자 Verified 확인, SMTP 키 암호화 저장, 서비스 재시작 완료.

체험용 **demo_host**에서 ‘[청모] 복구 이메일 인증’ 1통을 실제 발송했다. Brevo **Sent / Delivered** 기록과 사용자의 Gmail 수신 확인으로 검증했다. 체험 계정 비밀번호를 바꾸지 않았고 수신 확인만으로 복구 연락처를 인증 완료하지 않았다.

도메인이 없어 실제 From이 `chungmo7942@12445735.brevosend.com`으로 치환된 것을 로그에서 확인했다. 도메인을 확보하면 전용 주소와 DKIM/DMARC로 전환한다. [발신 도메인 안내](https://help.brevo.com/hc/en-us/articles/16045394674066-Troubleshooting-issues-with-domain-authentication). 공식 무료 플랜은 하루 300통이며 실제 한도는 계정에서 확인한다. [무료 한도](https://help.brevo.com/hc/en-us/articles/208580669-FAQs-What-are-the-limits-of-the-Free-plan).

## 검증

전체 자동 테스트 54개 통과와 로컬 빌드 완료. 인증 전 연락처 비활성, 일회성·만료·목적 구분, 게스트 설정 차단, CSRF, 마스킹 아이디 응답·원문 비노출·추가 메일 없음·짧은 아이디·이메일 대소문자 정규화, 재설정 후 기존 세션 차단·이전 비밀번호 거부·새 비밀번호 로그인, 요청 제한 검증. 브라우저에서 기존 호스트 설정 진입·실제 메일 발송·Gmail 수신과 Brevo 전달 기록 확인. 운영 도메인의 링크 열람은 배포 후 별도 검증한다.
