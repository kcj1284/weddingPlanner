# 초대 목록의 코드 확인과 재전송

호스트의 **초대하기 → 초대 목록 → 코드 확인 · 재전송**에서 해당 친구의 초대코드와 개인 링크를 확인한다. 코드 복사·링크 복사·카카오톡으로 재전송을 제공한다. 전송할 친구는 사용자가 카카오톡에서 직접 선택하며 자동 발송하지 않는다. 취소된 초대에는 기능을 제공하지 않는다.

신규 초대는 조회용 SHA-256 해시와 복구용 AES-256-GCM 암호문을 함께 저장한다. 암호문은 링크 ID를 인증 데이터로 사용해 다른 링크로 옮겨 복호화할 수 없다. 목록 API에는 코드나 암호문을 포함하지 않는다. 코드는 호스트가 개별 확인 API를 요청할 때만 복호화하며 응답에는 Cache-Control: no-store를 적용한다.

V5 이전 초대는 해시만 있으므로 원문 복구가 불가능하다. 코드 확인을 누르면 **새 코드 발급 후 재전송**을 안내한다. 사용자가 이 버튼을 눌러야 재발급하며, 단순 확인으로 기존 초대를 변경하지 않는다. 재발급은 같은 초대 레코드의 코드와 만료일만 바꾸고 게스트 계정·모임 참여·투표를 유지한다. 이전 코드와 링크는 무효화하며 새 코드는 30일 유효하다. 만료된 초대도 동일한 흐름으로 갱신한다. 취소한 초대는 복구하지 않는다.

단체 초대에서 신규로 참여한 게스트의 개인 재접속 코드도 암호화 보관한다. 기존 단체 참여자의 43자리 개인 링크는 필요 시 6자리 코드로 재발급할 수 있으며 참여 기록은 유지된다. 단체 공통 링크에는 이번 원문 확인 기능을 적용하지 않는다.

## 암호화 키

로컬 scripts/env.ps1은 최초 한 번 32바이트 난수 키를 만들어 ignored data/invite-code-key.dpapi에 현재 Windows 사용자용 DPAPI로 저장한다. 이후 재시작에서도 같은 키를 읽는다. 키 원문은 로그나 저장소에 기록하지 않는다.

배포에서는 **INVITE_CODE_ENCRYPTION_KEY**에 Base64로 인코딩한 32바이트 난수를 비밀 환경 변수로 설정한다. 키를 서버 재시작마다 바꾸면 기존 암호문을 읽을 수 없으므로 지속적으로 보관하고 DB 백업과 함께 키의 복구도 준비한다. 로컬 DPAPI 파일은 해당 Windows 사용자 환경에 묶여 있으므로 서버로 그대로 복사하는 방식으로 배포하지 않는다. 테스트 프로필의 고정 키는 테스트 전용이다.
