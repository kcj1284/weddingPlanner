# 빠른 장소 검색과 청모 관련 글

장소 목록을 먼저 반환하며, 관련 글은 별도 작업과 `/places-reviews` 조회로 업데이트한다. UI는 최대 2분 동안 2초 간격으로 상태를 확인하며 완료 시 중단한다. 다른 검색·모임·탭으로 이동한 결과는 적용하지 않는다. 후기 실패 시 장소 목록을 유지한다.

## 정렬과 출처

네이버 검색 API가 연결되면 지역 검색 `sort=comment`의 카페·블로그 리뷰 많은 순 후보 최대 5곳을 사용한다. 청모 관련 글이 확인된 후보를 먼저 표시하고 같은 그룹 안에서는 원래 리뷰순을 유지한다. 방문자 리뷰 수나 별점순이 아니며 실제 리뷰 숫자를 제공하거나 만들어 표시하지 않는다.

식당 이름과 주소의 시·구 정보에 청모 / 청첩장모임 / 청첩장 모임을 각각 붙여 블로그 검색한다. 제목·요약에서 식당 이름과 모임 키워드를 함께 확인하고 URL 중복을 제거해 최대 3개 원문 링크와 작성일을 제공한다. 본문 전체를 수집하지 않으며 실제 방문·지점 일치·광고 여부는 보장하지 않는다.

네이버 연결이 없으면 기존 카카오 정확도순 최대 15곳을 유지하고 화면에 연결 상태를 설명한다. 네이버 지역 검색 실패 시에도 카카오로 전환하며 리뷰순으로 표시하지 않는다.

## 캐시와 갱신

Flyway V3의 place_discovery_cache에 지역+검색어+장소 종류 결과와 식당별 후기 결과를 별도로 보관한다. 일반 결과와 빈 후기 결과 모두 24시간 재사용한다. 오래된 결과는 즉시 제공하면서 뒤에서 갱신한다. 후기 실패는 기존 글을 유지하며 1시간 후 재시도한다.

후기 작업은 최대 2개 동시 실행, 대기 20개, 같은 작업 중복 실행 방지로 제한한다. 전체 리뷰 수에 청모 검색 결과 숫자를 더하거나 이를 실제 리뷰 수로 해석하지 않는다. 네이버 최대 5곳이면 최초 지역 검색 1회와 후기 검색 최대 15회가 필요하지만 목록 반환은 후기 조회를 기다리지 않는다.

시간마다 최근 7일 동안 사용된 만료 캐시를 최대 20개 갱신한다. 따라서 매일 만료된 데이터가 갱신되며, 앱이 실행 중일 때만 동작한다. 30일 동안 사용되지 않은 캐시는 정리한다. 서버 여러 대의 작업 중복 방지는 별도 분산 작업 시스템이 필요하다.

## 네이버 연결

네이버 개발자 센터 앱의 사용 API에 **검색**을 추가한다. 로그인 API 권한과 별개다. 아래 스크립트는 Client ID와 Client Secret을 화면에 노출하지 않고 현재 Windows 사용자의 DPAPI로 저장한다. 파일은 ignored data 폴더에만 보관한다.

```powershell
./scripts/set-naver-search.ps1
```

저장 후 서버를 재시작한다. 서버 배포에서는 NAVER_SEARCH_CLIENT_ID / NAVER_SEARCH_CLIENT_SECRET을 서버의 비밀 환경 변수로 설정한다. 키는 클라이언트에 전달하지 않는다.

2026-10-12 기준 실제 네이버 검색 키는 미연결이다. 자동 테스트의 로컬 가짜 API로 비동기 반환, 캐시 재사용, 관련 글 필터·중복 제거·우선 표시, 만료 캐시 즉시 응답을 확인했다. 전체 38개 테스트 통과. 실제 키 연결 후 네이버 결과와 쿼터를 최종 확인해야 한다.

2026-10-13 보강: 지점의 캐시 신원은 상호명과 전체 주소로 구분한다. 장소 목록 갱신도 pending 상태에 포함해 최신 목록이 현재 화면에 반영되도록 한다.
