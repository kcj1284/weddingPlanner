# 모바일 청첩장 축의금 계좌

편집기의 `05 축의금` 단계에서 계좌 공개 여부, 섹션 제목, 안내 문구를 설정한다. 신랑측과 신부측에 각각 최대 4개(전체 8개)의 계좌를 추가할 수 있으며, 관계·은행명·예금주·계좌번호를 입력한다. 관계는 신랑, 신부, 아버지, 어머니 등 직접 지정한다.

공개 청첩장의 “마음 전하실 곳”에서 양측 계좌를 펼쳐 볼 수 있다. 복사 버튼은 계좌번호의 하이픈과 공백을 제거한 숫자를 복사한다. 클립보드 사용이 불가능하면 계좌번호를 선택하여 직접 복사하도록 안내한다. 이 기능은 계좌 안내용이며 송금·결제·계좌 실명 확인을 수행하지 않는다.

공개 설정은 기본적으로 꺼져 있다. 꺼진 상태에서는 저장된 계좌를 편집기에 유지하고 공개 API 응답에서는 제외한다. 발행 전까지 공개 링크는 404이며, 발행 취소 후에도 404로 보호한다. 발행 확인 안내에 계좌 공개 범위를 명시했다. 입력 값은 HTML로 실행하지 않고 이스케이프한다. 기존 소유자 확인, CSRF, 버전 충돌 방지를 그대로 적용한다.

`invitation.payload` JSON에 선택 항목 `giftAccounts`를 추가했다. 기존 데이터에서는 null로 읽혀 계좌 섹션이 표시되지 않는다. DB 스키마 변경이나 기존 청첩장 일괄 수정은 없다.

## 참고한 레퍼런스

- 사용자가 제시한 [바른손카드 셀프 제작](https://www.barunsoncard.com/Product/SelfpickList?category=all&sort=recommended)
- [바른손M카드 공식 FAQ](https://mcard.barunsoncard.com/Customer/Faq): 모바일 청첩장 작성 단계의 계좌 등록 및 신랑측·신부측과 혼주 구분 안내를 참고했다. 카드결제·포인트·출금 기능은 이번 구현 범위에 포함하지 않았다. 접히는 양측 목록과 복사 버튼은 청모의 기존 화면에 맞춰 구현했다.

## 검증

- 계좌 저장·발행·공개 취소, 비공개 설정 시 공개 응답 제거, 기존 JSON 호환성.
- 잘못된 계좌 문자, 양측 구분, 공개 계좌 없는 상태, 한쪽 4개 초과 입력 거부.
- 공개 페이지에서 사용하는 JS 모듈의 익명 접근.
- PostgreSQL 테스트 DB에서 전체 자동 테스트 34개 통과.
