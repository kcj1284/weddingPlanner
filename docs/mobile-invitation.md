# 모바일 청첩장 사용 안내

## 제작과 공유
1. 청모에서 호스트 계정으로 로그인한다. 기존 카카오·구글·네이버 로그인도 같은 세션을 사용한다(제공자 키 설정 필요).
2. 메뉴의 **모바일 청첩장 / 청첩장 만들기** 또는 `/invitation.html`을 연다.
3. 클래식 레터, 그린 가든, 포토 스토리 중 디자인을 선택한다. 신랑·신부 이름, 초대의 글, 예식 일시, 예식장 이름과 주소를 입력한다. 부모님 소개·연락처·교통 안내는 선택이다.
4. 대표 사진과 갤러리 최대 6장을 추가한다. JPEG·PNG 원본은 최대 20MB이며 브라우저가 긴 변 1600px 이하 JPEG로 압축한다. 서버는 이미지당 500KB, 긴 변 4096px, 1600만 픽셀 이하 및 실제 이미지 형식을 검증한다.
5. **청첩장 저장**을 누른다. 초안은 비공개다. 재접속하면 나의 청첩장 목록에서 선택해 이어서 편집한다.
6. **저장하고 발행하기**를 누르고 공개 범위 안내를 확인한다. 발행된 URL은 `/invitation.html?card=<128비트 임의 토큰>`이다. 링크를 가진 사람은 가입 없이 볼 수 있다.
7. 링크 복사·브라우저 기본 공유 기능으로 전달한다. 공개 화면에서 지도 검색과 일정 파일(`wedding.ics`) 다운로드를 제공한다. 일정은 한국 시간을 UTC로 변환한다.
8. 발행 후 저장한 변경은 공개 화면에 즉시 반영된다. **발행 취소**는 이후 공개 API 요청을 차단한다. 이미 열람·다운로드한 내용까지 회수하지는 않는다.

공개 청첩장 링크는 기존 청모의 6자리 개인 초대코드와 별개다. 청첩장 링크에는 청모 참여·투표 권한이 없다. 연락처와 사진은 호스트가 공개할 항목만 입력한다.

### 예식장 주소 검색

**예식 정보 → 예식장 주소 → 주소 검색**을 누르면 화면 안에 카카오 우편번호 검색이 열린다. 도로명·지번·건물명으로 검색하고 결과를 선택하면 주소 입력과 미리보기에 반영된다. 선택 후 주소 칸에 층·홀 등 상세주소를 덧붙일 수 있고 직접 입력도 가능하다. 검색 닫기는 기존 입력을 유지한다. 주소 변경은 **저장하기**를 눌러 보관한다.

[카카오 공식 안내](https://postcode.map.kakao.com/guide)에 따라 별도 API 키 없이 무료로 사용한다. 검색 버튼을 누를 때 SDK를 로드하며 연결 실패 시 재시도 또는 직접 입력을 안내한다. 운영은 HTTPS로 배포한다. HTTP 검색 프레임은 localhost 개발을 위한 local 프로필에서만 허용한다.

검증(2026-10-13): 자동 테스트 47개와 로컬 패키지 빌드 통과. 실제 ‘세종대로 110’ 검색 결과 선택 후 주소·미리보기 반영과 검색창 닫힘을 확인했다. 모바일 390px에서 결과·제공자 로고 표시, 가로 넘침 없음과 브라우저 오류 없음 확인. 화면 기록: `artifacts/invitation-address-search.png`. SDK가 만드는 about:blank 프레임에는 자체 CSS를 연결해 기존 인라인 스타일 제한을 유지한다.

## 실행과 배포
### 자유 편집 사용법
편집 화면의 **문구 편집 단계**에서 자유 편집 표지를 켠다. 기본 이름·초대 문구·예식 정보가 편집 가능한 글자 객체로 표시된다. 기존 상세 예식 안내는 표지 아래에 유지된다.

- 텍스트를 선택하고 미리보기에서 드래그하거나 X/Y 위치를 입력한다. 방향키로 1칸, Shift + 방향키로 10칸 이동한다. 360 단위 좌표가 모바일 화면 너비에 맞게 비례 축소된다.
- **텍스트 추가**로 최대 30개까지 문구를 배치한다. 개당 500자, 크기·색·정렬·굵기·영역 너비를 변경한다. 연동 텍스트는 기본 정보의 변경을 따라간다. 직접 입력을 선택하면 독립 문구가 된다.
- 전체 본문과 개별 문구의 글씨체를 따로 고른다. 나눔명조·나눔고딕·나눔손글씨 펜·나눔손글씨 붓·고운돋움·고운바탕 및 시스템 기본을 제공한다.
- 표지 높이(360~1000), 배경색, 대표 사진 배경을 선택한다. 긴 문구는 글씨 크기·영역 너비·표지 높이를 조절해 넘치지 않도록 미리보기를 확인한다.
- **QR 추가**로 최대 5개까지 배치한다. 이 청첩장 링크 또는 직접 입력한 HTTP(S) 링크를 연결하고 위치·크기(60~200)·패턴(사각·둥근·도트)·외곽(사각·둥근·원형)을 고른다. 흰 여백은 인식을 위해 유지되며 원형이나 긴 URL은 크기 160 이상을 권장한다.
- 자동 청첩장 QR은 저장 후 생성된다. 열람은 발행 후 가능하다. localhost QR은 다른 기기에서 해당 PC로 연결되지 않으므로 외부 공유는 배포 주소에서 생성한다.
- 변경 후 **청첩장 저장**을 사용한다. 발행 중인 청첩장은 저장 즉시 공개 화면에도 반영된다.

저장된 이전 청첩장은 호환된다. 선택적 JSON 필드이므로 추가 DB migration이 없다. [폰트 및 QR 자산 출처](fonts-and-qr.md).

기존 `scripts/run.ps1`을 사용한다. Flyway V2가 invitation 테이블을 추가하며 기존 청모 데이터는 유지한다. 사진도 DB에 포함되므로 DB 백업으로 함께 보존된다. 원본 사진은 저장하지 않는다. 계정당 최대 20개이며 초기 규모에서는 이미지도 DB에 저장한다. 서비스가 커지면 객체 저장소로 이관을 고려한다.

배포 시 사진 포함 JSON 요청을 받을 수 있도록 역방향 프록시의 본문 크기 제한을 **6MB 이상**으로 설정한다. 공유 URL은 현재 접속한 도메인으로 생성되므로 실제 외부 공유는 HTTPS 배포 후 사용한다. localhost 링크는 해당 PC에서만 열린다. 카카오 SDK 전용 공유·SNS 미리보기 카드·RSVP·계좌·방명록·인쇄 주문은 포함하지 않는다.

## 검증 기록 (2026-10-12)
- PostgreSQL 전체 자동 테스트 28개 통과: 소유권, 게스트 제작 금지, CSRF, 초안 비공개, 공개 응답 범위, 발행 취소, 이전 버전 저장 충돌, 잘못된 사진 거부 포함.
- 브라우저에서 호스트 진입, 그린 가든 선택, 예식 정보 저장, 대표·갤러리 사진 업로드, 발행 및 공개 열람, 발행 취소 후 차단 확인.
- 390px 모바일 공개 화면의 가로 넘침 없음과 사진 로딩 확인. 일정 파일 다운로드 후 `2027-05-22 13:00 Asia/Seoul`이 `20270522T040000Z`로 변환됨 확인.
- 로컬 DB에 합성 사진을 사용한 도윤·지은 예제 청첩장 1개가 있다. 실제 예식·사진 데이터가 아니다.
- 적용 전 백업: `data/backups/pre-invitation-20261012.dump`. 기존 V1 테이블을 바꾸지 않은 추가 migration이다.

참고: [바른손카드 셀프 제작 목록](https://www.barunsoncard.com/Product/SelfpickList?category=all&sort=recommended)의 디자인 선택 흐름을 참고했다. 상품 이미지·로고·상품명·유료 디자인은 사용하지 않았다.

### 제작 화면 개선

디자인 → 예식 정보 → 사진 → 문구 편집 → 축의금 → 확인·공유의 여섯 단계를 **이전·다음**으로 진행한다. 현재 단계와 진행률을 표시하고 **단계 바로가기**로 원하는 작업을 선택할 수 있다. 필수 입력이 누락되면 해당 입력을 안내한다. 마지막에는 이름·초대 문구·날짜·장소·주소와 계좌 공개 여부를 확인하고 저장·발행한다.

모바일에서는 하단 미리보기·저장을 항상 사용할 수 있다. 전체 미리보기에서 돌아오면 같은 편집 단계와 스크롤 위치로 복귀한다. 문구·QR을 직접 선택하면 문구 편집 단계로 이동한다. 데스크톱에서는 단계 탭과 편집·미리보기가 함께 보인다. 공개 QR을 눌러 연결 URL을 직접 열고, 갤러리 사진을 눌러 확대할 수 있다. 웨딩 타임즈를 선택한 경우 **문구 편집**에서 신문형 제목과 본문을 설정한다.
