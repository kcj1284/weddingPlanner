# Feature Specification: 청모 모바일 모임 조율

**Feature Branch**: 없음(현재 폴더는 Git 저장소가 아님)

**Created**: 2026-10-08

**Status**: Draft — 요구사항 품질 검토 완료

**Input**: 한국의 청첩장 모임을 위한 모바일 사이트. 장소·날짜·시간 투표,
호스트의 예약 가능한 식당·카페 탐색, 호스트와 게스트 분리를 제공한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 호스트가 청모를 만들고 초대 (Priority: P1)

사용자는 계정을 만들고 청모의 이름, 설명, 지역, 예상 인원을 입력해 모임을 만든다.
호스트는 초대 링크를 공유하고 게스트는 자신의 계정으로 참여한다.

**Why this priority**: 실제 여러 기기에서 함께 사용할 공간과 권한을 만든다.

**Independent Test**: 새 호스트가 모임을 만들고 다른 계정이 링크로 참여한다.

**Acceptance Scenarios**:

1. **Given** 인증된 사용자, **When** 유효한 모임 정보 제출, **Then** 해당 모임의 호스트가 되고 초대 링크를 받는다.
2. **Given** 링크를 받은 게스트, **When** 로그인 후 참여, **Then** 해당 모임만 조회하고 투표할 수 있다.
3. **Given** 비구성원 또는 게스트, **When** 다른 모임 조회 또는 관리 시도, **Then** 서버가 접근을 거부한다.
4. **Given** 이미 참여한 계정, **When** 같은 초대 재사용, **Then** 구성원이 중복 생성되지 않는다.

### User Story 2 - 날짜·시간과 장소 투표 (Priority: P1)

호스트는 날짜와 시간이 결합된 후보 및 장소 후보를 추가한다. 구성원은 가능한 후보를
복수 선택하고 투표를 수정한다. 호스트는 집계를 보고 최종 날짜·시간과 장소를 확정한다.

**Why this priority**: 여러 사람의 가능한 일정과 선호 장소를 모으는 핵심 기능이다.

**Independent Test**: 두 계정이 서로 다른 후보에 투표한 후 집계·수정·확정을 확인한다.

**Acceptance Scenarios**:

1. **Given** 열린 모임, **When** 게스트가 시간 및 장소 여러 후보에 투표, **Then** 후보별 인원과 본인 선택이 저장된다.
2. **Given** 이전 투표, **When** 수정 제출, **Then** 이전 선택을 대체하며 중복 인원이 생기지 않는다.
3. **Given** 열린 모임, **When** 호스트가 해당 모임의 시간 하나와 장소 하나를 확정, **Then** 모두에게 확정 내용이 표시되고 추가 투표·후보 추가를 거부한다.
4. **Given** 확정 모임, **When** 호스트가 다시 투표를 열기, **Then** 확정 선택을 해제하고 기존 후보·투표는 보존한다.

### User Story 3 - 호스트의 식당·카페 탐색 (Priority: P2)

호스트는 지역·검색어 및 식당/카페 종류로 실제 장소 정보를 탐색하고 지도·전화로
예약 여부를 문의한다. 원하는 장소를 투표 후보로 추가하고 확인 상태를 기록한다.

**Why this priority**: 호스트의 장소 준비를 돕고 조회 정보와 실제 예약 상태를 구분한다.

**Independent Test**: 호스트가 검색하고 후보를 추가한다. 외부 검색 설정이 없으면 안내 후 수동 입력한다.

**Acceptance Scenarios**:

1. **Given** 장소 검색이 설정됨, **When** 지역과 식당 또는 카페 검색, **Then** 이름·주소·전화·지도 상세 링크를 확인한다.
2. **Given** 검색 결과, **When** 후보 추가, **Then** 장소 투표에 반영하고 예약 상태는 미확인으로 시작한다.
3. **Given** 외부 검색 미설정 또는 장애, **When** 탐색, **Then** 상태를 정확하게 안내하고 수동 후보 입력을 제공한다.
4. **Given** 전화 등으로 확인한 장소, **When** 호스트가 예약 확인 상태를 변경, **Then** 미확인/예약 가능 확인/예약 완료 중 선택한 상태와 확인 메모를 표시한다.

### Edge Cases

- 시간 또는 장소 후보가 없으면 각각 후보 없음과 다음 행동을 안내한다. 미투표는 0명으로 표시한다.
- 동률이어도 호스트가 원하는 최종 후보를 선택할 수 있다. 최다 득표로 자동 확정하지 않는다.
- 다른 모임의 후보 ID, 잘못된 날짜·인원, 중복 후보 선택은 거부한다.
- 투표와 확정이 동시에 발생하면 먼저 확정된 이후 투표는 거부한다.
- 링크는 참여 권한을 가진 초대장이다. 링크를 가진 사람의 참여를 허용하되 계정 로그인이 필요하다.
- 초대 링크에는 로그인 인증 정보가 없으며 링크만으로 호스트 권한을 얻을 수 없다.
- 저장 실패는 성공으로 표시하지 않는다. 투표 저장은 한 번에 전체 선택을 대체한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 계정 생성, 로그인, 로그아웃과 모임 목록을 제공해야 한다. 비밀번호 원문은 보관하지 않는다. 수용 기준: 새 계정 로그인 및 로그아웃 후 보호된 작업 거부.
- **FR-002**: 모임은 이름 1–80자, 설명 최대 500자, 지역 1–80자, 예상 인원 2–100명으로 생성한다. 생성자를 호스트로 설정한다. 수용 기준: US1.1 및 경계값 검증.
- **FR-003**: 무작위 초대 링크로 인증된 사용자를 게스트로 참여시키고 반복 참여는 중복되지 않아야 한다. 수용 기준: US1.2, US1.4.
- **FR-004**: 권한은 모임별로 구분하며 조회·투표는 구성원, 후보 추가·예약 상태 관리·장소 검색·확정·재개는 호스트에게만 허용한다. 수용 기준: US1.3.
- **FR-005**: 날짜·시간 후보와 장소 후보를 각각 관리하고 최대 각 30개를 허용한다. 날짜·시간은 한국 시간으로 표시한다. 수용 기준: US2.1 및 후보 제한 검증.
- **FR-006**: 구성원은 시간과 장소 각각 복수 선택을 저장·수정할 수 있고 아무것도 선택하지 않은 제출은 투표 철회로 처리한다. 수용 기준: US2.1–2.2 및 철회 후 집계 0.
- **FR-007**: 후보별 득표수, 응답 구성원 수, 전체 구성원 수, 본인 선택을 표시하며 타인의 비밀번호·세션·초대 비밀을 응답에 포함하지 않는다. 수용 기준: 두 계정 집계와 응답 필드 검토.
- **FR-008**: 호스트는 시간 하나와 장소 하나를 확정하거나 투표를 재개할 수 있다. 확정 모임은 투표와 후보 변경을 차단한다. 수용 기준: US2.3–2.4.
- **FR-009**: 호스트는 지역·검색어·식당/카페 종류로 장소를 탐색하고 지도·전화 문의로 연결할 수 있다. 수용 기준: US3.1.
- **FR-010**: 검색 장애·미설정을 안내하고 수동 장소 추가를 제공한다. 장소 정보 검색이 실시간 예약 재고를 보장한다고 표시하지 않는다. 수용 기준: US3.2–3.3.
- **FR-011**: 호스트가 확인한 예약 상태와 최대 300자 메모를 표시한다. 예약 가능 여부는 확인 시점 정보이며 실제 예약 실행은 별도 외부 절차다. 수용 기준: US3.4.
- **FR-012**: 핵심 화면은 360px 모바일부터 데스크톱까지 사용 가능하며 키보드 조작, 레이블, 오류·빈 화면·저장 안내를 제공한다. 수용 기준: 화면 폭별 모든 주요 조작 완료.
- **FR-013**: 모든 투표 변경은 원자적으로 처리하고 다른 모임 후보·비구성원 투표·확정 이후 투표를 차단한다. 수용 기준: 오류 제출 시 기존 투표 보존 및 권한·동시성 자동 검증.

### Key Entities *(include if feature involves data)*

- **계정**: 사용자 ID, 로그인 이름, 표시 이름, 비밀번호 보호 값.
- **모임**: 호스트, 이름, 설명, 지역, 인원, 초대 비밀, 열린/확정 상태, 확정 시간·장소.
- **구성원**: 모임과 계정의 관계. 호스트 역할은 모임의 소유 관계로 결정한다.
- **후보**: 모임, 시간 또는 장소 종류, 제목·상세, 외부 장소 링크·전화, 예약 상태·메모.
- **투표**: 모임의 구성원과 선택 후보의 관계. 구성원당 후보별 최대 1표.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 대상 사용자 5명 중 4명 이상이 도움 없이 3분 내 모임 생성과 초대 공유를 완료한다.
- **SC-002**: 게스트 5명 중 4명 이상이 참여 후 1분 내 일정과 장소 투표를 완료한다.
- **SC-003**: 두 계정의 반복 투표·철회·확정 시나리오에서 집계 오류와 확정 후 허용된 투표는 0건이다.
- **SC-004**: 게스트·비구성원의 호스트 관리 작업 및 다른 모임 접근을 모두 거부한다.
- **SC-005**: 360px, 390px, 768px, 1280px 화면에서 수평 페이지 넘침 없이 주요 조작을 완료한다.
- **SC-006**: 검색 실패·미설정 시나리오 100%에서 수동 후보 입력으로 준비를 계속할 수 있다.

## Assumptions

- 기존 웨딩 준비 명세는 보관하고 본 청모 명세를 활성 기능으로 사용한다. 예산·하객·계약 관리는 이번 범위 밖이다.
- 모든 사용자는 간단한 계정을 사용한다. 역할은 사용자의 전체 계정이 아니라 각 모임에서 결정한다.
- 한국어, 한국 시간, 모바일 웹을 우선한다. 투표는 날짜와 시간을 결합한 후보 및 독립된 장소 후보로 진행한다.
- 식당·카페 검색은 외부 장소 정보 제공자의 설정이 필요하다. 실시간 예약 재고·자동 예약·결제는 해당 제공자의 연동 계약과 자격 정보가 없는 현재 범위에서 제외한다.
- 장소의 예약 상태는 호스트가 직접 확인해 기록한다. 참가 인원과 날짜에 따른 최종 예약은 외부 제공자에게 다시 확인한다.
- 이번 구현은 가입·초대·투표·검색·확정을 수행하는 MVP다. 계정 복구, 소셜 로그인, 초대 철회, 모임 삭제·보존 자동화, 알림은 후속 범위다.
- 헌장 II의 인증·접근 원칙은 모임별 계정과 구성원 관계로 적용한다. 데이터 삭제·보존은 출시 전 후속 명세 및 운영 정책으로 검증해야 하며 이번 MVP를 출시 완료로 해석하지 않는다.
- 구현에 권한·투표 집계·확정 및 외부 검색 오류의 자동 테스트를 요구한다.

## 추가 요구사항: 게스트 무가입 및 호스트 소셜 로그인

FR-017: 호스트만 개인별 게스트 URL을 발급·목록 조회·취소할 수 있다. 링크당 한 게스트가 연결되며 최초 접속에서 이름만 받는다. 가입과 비밀번호는 요구하지 않는다.
FR-018: 같은 링크의 재접속은 기존 참여자와 투표를 유지한다. 링크는 30일 동안 신규 접속이 가능하며 취소 시 기존 세션도 모임 권한을 잃고 기존 투표가 제거된다. 취소 전에 화면에서 확인한다.
FR-019: 무가입 게스트는 투표와 해당 모임 조회만 가능하고 모임 생성·초대 관리·장소 검색·확정은 불가능하다.
FR-020: 호스트는 가입 후 모임을 생성한다. 카카오·구글·네이버 로그인 완료 시 계정을 자동 생성하며 제공자와 고유 사용자 ID로 식별한다. 앱 키가 없으면 비활성 상태를 표시하고 기존 가입·로그인을 제공한다.
FR-021: 개인별 링크는 대문자 영문·숫자를 섞은 6자리 난수로 생성하고 원문은 발급 시에만 반환한다. 링크를 소지한 사람이 해당 게스트 권한을 가진다는 안내를 제공한다. 이메일 자동 병합은 하지 않는다.

이 요구사항은 최초 명세의 가입 기반 게스트 참여 조건을 대체한다. 기존 공통 초대 코드는 이전 가입 계정의 호환성을 위해 유지한다. 실제 소셜 인증 왕복 검증에는 세 제공자의 앱 키와 등록된 콜백이 필요하다.

FR-022: 게스트는 비로그인 상태에서도 초대받은 모임 메뉴에서 개인별 6자리 대문자 영문·숫자 코드를 입력한다. 최초 확인 후 이름을 입력하고 참여한다. 재접속은 기존 이름과 투표를 유지한다. 잘못되거나 만료/취소된 코드에는 오류를 표시한다. 신규 코드는 영문·숫자를 모두 포함하고 I/O/0/1을 제외하며 전역 중복을 방지한다. 기존 긴 코드·전용 링크도 유지한다.
