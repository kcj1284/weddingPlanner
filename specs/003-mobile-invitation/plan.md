# 구현 계획

- 기존 Spring Boot / JavaScript / PostgreSQL 및 인증 세션을 재사용한다. 추가 라이브러리 없이 전용 편집 화면과 공개 화면을 같은 페이지에서 제공한다.
- Flyway V2는 기존 테이블을 변경하지 않고 invitation 테이블을 추가한다. 사진 포함 JSON을 TEXT로 저장하고 버전으로 낙관적 잠금을 구현한다. 초기 규모에서 운영 단순성을 우선한다. 향후 사진 용량이 늘면 객체 저장소 이관이 필요하다.
- 모든 쓰기는 호스트 인증·소유권·CSRF를 검사한다. 입력은 길이, 일시, 전화번호, 템플릿을 검증하고 사진은 JPEG/PNG 시그니처·크기·픽셀 수를 확인한다. 공개 응답에는 청첩장 본문만 반환한다.
- 헌장 개인정보 접근 원칙의 공개 청첩장 예외: 공유 가능한 모바일 청첩장이라는 사용자 요청이 승인 근거다. 초안은 비공개이며 호스트가 명시적으로 발행할 때만 선택한 본문을 공개한다. 편집 화면에서 링크 보유자에게 이름·사진·연락처가 공개됨을 안내한다.
- 개인정보 로그 금지, 모바일 접근성, 데이터 변경 안전성, 한국 시간, 위험 기반 검증을 준수한다. 기존 테이블과 데이터는 유지한다. 로컬 DB 백업 후 V2를 적용한다. 되돌릴 때 V2 데이터를 내보내고 이전 앱을 실행할 수 있다(기존 테이블 변경 없음).

## 자유 편집 확장
- JSON payload에 선택적 design 필드를 추가한다. 기존 행은 design=null로 열리므로 SQL 변경이나 기존 데이터 덮어쓰기가 필요 없다.
- 360 단위 SVG 표지를 사용해 휴대폰 너비와 관계없이 텍스트·QR 배치를 유지한다. Pointer Events 드래그, 숫자 좌표 및 키보드 이동을 제공한다. 임의 CSS나 HTML을 저장하지 않고 글꼴·정렬·색상·좌표를 서버에서 검증한다.
- Google Fonts의 SIL OFL 글꼴 6종을 라이선스와 함께 자체 호스팅한다. 브라우저용 WOFF2로 압축하며 추가 외부 런타임 연결은 하지 않는다.
- 실제 QR 생성에 Apache 2.0 ZXing core 3.5.3을 사용한다. URL을 외부 서버로 전송하지 않으며 서버가 대상 URL을 방문하지도 않는다. 각 모양은 흰 quiet zone과 사각 finder를 유지하고 실제 decode 테스트를 통과해야 한다.
- QR 주변 여백·검정 패턴은 스캔 품질을 위해 고정한다. 원형 외곽 및 긴 URL에서는 큰 크기를 권장한다. 실기기 카메라 품질은 조명·화면·출력 상태에 영향을 받는다.

## Product Design 개선
실제 모바일 화면을 캡처한 후 확인된 제작 진입·스크롤·저장·읽기 순서 문제를 기존 디자인 언어 안에서 수정한다. 전후 증거와 제한은 docs/design-audit-20261012/report.md에 기록한다. 추가 의존성 없이 기존 폼을 단계별 패널로 묶고, 동일한 저장 API를 유지한다. Lucide 아이콘은 라이선스와 함께 자체 호스팅한다. 이 변경에는 DB migration이 없다.
